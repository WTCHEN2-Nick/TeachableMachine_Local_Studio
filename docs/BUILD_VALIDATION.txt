Teachable Machine Local Studio v2.1.0 Windows Only - Build Validation
=====================================================================
Build date: 2026-09-02 (v2.0.7 baseline), 2026-09-12 (v2.1.0 additions)

Release objective
-----------------
- Native Windows-only Python 3.13 project environment.
- Training runtime is always windows_tensorflow_cpu / Windows CPU.
- Image and Audio project behavior remains available.
- Abnormal Sound is a third project type using a frozen, pinned YAMNet
  embedding encoder plus a Normal-only one-class anomaly scorer.
- Known Sound is a fourth project type: a frozen YAMNet encoder plus a
  trainable multi-label sigmoid head that names the sound.
- v2.1.0: Image, Audio and Known Sound models can be built into NuMaker-M55M1
  or NuGestureAI-M55M1 firmware using the Arm GNU Toolchain. GCC only; Keil is
  not required and no Keil project is produced. The toolchain is installed by
  the user and is not bundled.

v2.1.0 addition: MCU firmware deployment
----------------------------------------
The automated suite gained dedicated coverage for the firmware path. Tests that
need the Arm GNU Toolchain (or MSVC for the Known Sound host golden comparison)
skip themselves when it is absent, so a machine without it still runs green.

- mcu_toolkit vendoring: manifest completeness, no .bat/.uvprojx/.uvoptx/.git,
  patched linker script and FatFs configuration (tests/test_mcu_vendoring.py).
- Build recipe derived from the progen records, compared against the recorded
  reference recipe (tests/test_mcu_records.py).
- Code generation: labels, model array, tensor-arena formula, token
  substitution, Known Sound threshold codes (tests/test_mcu_codegen.py).
- KWS log-mel tables regenerated from the training front end and replayed in
  NumPy: element-wise equality with mel_filterbank() and a quantized difference
  of at most 1 LSB against log_mel_spectrogram() (tests/test_kws_codegen.py).
- Deploy contract, board locks and the Chinese refusal messages
  (tests/test_mcu_contract.py, tests/test_mcu_deploy_guard.py).
- Deploy job, download token and flash endpoint guards
  (tests/test_mcu_deploy_api.py, tests/test_mcu_flash.py).
- Real firmware builds for image, Known Sound and KWS on both boards, including
  the linked size limits (tests/test_mcu_image_build.py,
  tests/test_mcu_known_sound_build.py, tests/test_mcu_kws_build.py).
- USB CDC retarget seam: the compiled _write() reaches the CDC tee
  (tests/test_mcu_cdc_sources.py).
- Known Sound C front end against Python golden vectors
  (tests/test_known_sound_frontend_host.py, needs MSVC).
- Tunable training settings, board locks and the INT8/Float agreement warning
  (tests/test_tunables_config.py, test_image_tunables.py, test_audio_tunables.py,
  test_known_sound_tunables.py, test_export_warnings.py).
- Reference scripts compile and expose --help (tests/test_reference_scripts.py).

Not validated: no firmware produced by this branch has been executed on real
hardware. See the "Known limitations and untested items" section of
docs/MCU_DEPLOY_zh-TW.md for the full list, which includes the non-cacheable
linker section, the GestureAI DMIC channel 2 wiring, the GestureAI UVC+CDC
composite device, the NuMaker-M55M1 debug UART port, and the Known Sound
depth-12 firmware for the NuMaker-M55M1 board.

Scope boundary
--------------
This validation proves that the new project, data collection, training,
Preview, export, and reference-runtime paths execute correctly. It does not
claim a target-machine fault-detection accuracy before representative GestureAI
DMIC Normal and fault recordings are collected and evaluated with held-out
recording sessions. The approximately 3.3 MiB integer YAMNet embedding core is
the Desktop/Advanced backend; strict integer conversion alone does not prove
flash, SRAM arena, operator resolver, or latency suitability for a specific MCU.
